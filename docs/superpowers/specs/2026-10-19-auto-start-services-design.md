# 桌面应用一键启动全部服务设计

## 目标

用户双击 Mac 或 Windows 正式版桌面应用后，不需要手动启动 Spring Boot；Electron 主进程自动启动后端、等待健康检查通过，再让问答界面进入可用状态。

## 范围与约束

- 保留现有 Electron + React + Spring Boot 架构，不把后端逻辑迁移到渲染进程。
- API Key 继续只由 Spring Boot 进程读取，Renderer 不接触密钥。
- 开发环境和正式打包环境使用同一个后端进程管理接口，但启动命令可不同。
- 正式版 Mac arm64 和 Windows x64 均必须支持自动启动。
- 不增加登录、设置中心、模型市场等未约定页面。

## 运行时架构

```text
Electron Main
  └─ BackendProcessManager
       ├─ 启动 Spring Boot（开发环境 Maven，打包环境 JAR）
       ├─ 注入 AI 环境变量
       ├─ 轮询 GET /api/v1/health
       ├─ 记录启动输出和退出原因
       └─ 应用退出时优雅终止后端
```

后端健康检查成功后创建主窗口；启动期间窗口显示“正在启动后端服务”，失败则显示失败原因和重试入口。问答 IPC 在后端未就绪时返回明确的可重试错误，避免用户看到空白加载状态。

## 正式版运行时

- Electron 包含 Spring Boot 可执行 JAR。
- 每个平台包含匹配架构的 Java Runtime，正式版不要求用户预装 Java。
- 后端固定优先使用本地回环地址；默认端口为 8080，启动前检查端口占用。
- 若端口被本应用以外的进程占用，启动失败并提示释放端口；不静默改端口，避免前后端配置不一致。
- JAR、Java Runtime 和日志路径使用 Electron `process.resourcesPath` 与用户数据目录解析，开发路径和打包路径不得混用。

## 生命周期与异常处理

1. `app.whenReady` 后启动后端进程。
2. 最多等待 30 秒，每 500ms 请求一次 `/api/v1/health`。
3. 后端启动失败、提前退出或超时，主窗口仍可打开，但进入服务不可用状态并允许重试。
4. 应用退出时发送优雅终止信号，等待最多 3 秒，超时后仅终止本次启动的后端进程。
5. 保存后端 stdout/stderr 到用户数据目录的轮转日志，不记录 API Key、问题正文或答案正文。
6. 防止同一个桌面应用实例重复拉起多个后端；跨实例启动冲突通过端口检测和单实例锁处理。

## 打包、签名与升级

- Electron Builder 的 Mac/Windows 配置分别包含后端 JAR 和平台 Java Runtime。
- 构建脚本在打包前检查 JAR、Runtime 和架构，缺少任一文件时失败并给出路径。
- Mac 目录包、Windows x64 目录包均需验证后端进程实际启动、健康检查通过和退出清理。
- 文档记录签名、公证和 Windows 杀毒软件误报的发布前检查项；不在本阶段伪造签名证书。
- 记录新增包体积和启动耗时，作为后续升级包优化依据。

## 资源与用户体验

- UI 显示启动状态、启动失败原因和“重新启动服务”按钮。
- 服务就绪前禁用提问发送按钮；服务恢复后自动恢复。
- 启动成功后不显示开发日志；详细日志仅写入本地日志文件。
- 后端资源占用属于已接受的正式版成本；通过 JVM 内存参数和生命周期清理避免残留进程。

## 验收标准

- 双击 Mac/Windows 正式版后，用户无需终端或手动 Java 命令即可提问。
- 后端未启动、端口冲突、启动超时、后端崩溃和应用退出均有可理解的状态或日志。
- 应用退出后不存在由本应用创建的残留 Spring Boot/Java 进程。
- 原有前端、后端、IPC、AI 和打包测试继续通过。
